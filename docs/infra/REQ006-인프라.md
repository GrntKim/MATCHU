# REQ006 (E, 인프라)

| 항목 | 내용 |
| --- | --- |
| 요구사항 ID | REQ-006 |
| 요구사항명 | 사이트 전반 로직 및 인프라 |
| 담당 파일 | `app/main.py`, `app/lib/`, `app/static/`, `app/templates/`, 배포 전반 |
| 담당자 | 김준명 (E) |

본 문서는 각 에이전트가 협업하는 공통 기반(DB 연결, LLM 호출, 타입 계약), 계정·이력·사용량 관리, 이 서비스를 실제 사용자에게 노출하는 웹 인터페이스, Cloud Run 배포 전반에 대한 요구사항을 정의한다. 검증·오케스트레이션 로직은 REQ-005(D) 문서에서 별도로 다룬다.

**핵심 설계 원칙**

- **인프라 최소 구성**: 별도 서버(Compute Engine, 별도 백엔드 프레임워크) 없이 단일 Cloud Run 서비스로 배포를 완결한다.
- **공통 유틸리티 집중 관리**: DB 연결·LLM 호출·타입 계약처럼 여러 에이전트가 공유하는 코드는 `lib/`에 모아 중복을 방지한다.
- **파일 소유 경계**: E는 `main.py`, `lib/`, `static/`, `templates/`, 배포 파이프라인을 소유하며, 판단 로직(`agents/validate/`, `agents/orchestrate.py`)은 D(REQ-005)가 소유한다.
- **도메인은 GCP 네이티브로 충분하다**: Cloud Run이 발급하는 `*.run.app` 주소를 그대로 쓰며 관리형 인증서로 HTTPS가 즉시 적용된다. 별도 프록시나 DNS 연결은 두지 않는다.

**하위 기능 구성**

- INFRA-001: 배포 아키텍처
- INFRA-002: 공통 유틸리티
- INFRA-003: 계정·이력·사용량 관리
- SITE-001: 웹 인터페이스

## 1. 배포 아키텍처 (INFRA-001)

단일 FastAPI 서비스를 Cloud Run에 배포하고, Cloud SQL(`curriculum_chunks` 포함)과 Gemini API에 연결한다.

| 항목 | 내용 | 핵심 포인트 |
| --- | --- | --- |
| 입력 | 소스 코드(GitHub `main` 브랜치) | 배포는 수동. 머지 시 자동 반영되지 않는다 |
| 처리 | `gcloud run deploy --source .`로 이미지 빌드 후 새 리비전 배포 | 별도 Compute Engine 불필요, 서버리스 |
| 출력 | `*.run.app` 주소. 관리형 인증서로 HTTPS 즉시 적용 | 별도 도메인 연결 없음 |
| 예외 처리 | 배포 실패 시 이전 리비전 트래픽 유지 | Cloud Run 기본 동작 |

### 1.1 필수 배포 옵션

옵션을 누락하면 로컬에서는 멀쩡한 기능이 배포 환경에서만 조용히 실패한다.

| 옵션 | 없으면 생기는 문제 |
| --- | --- |
| `--no-cpu-throttling` | 파이프라인은 응답을 이미 반환한 뒤 백그라운드에서 실행된다(`app/main.py`의 `_run_generation`). 기본값은 응답 종료 시 CPU를 회수하므로, 이 옵션이 없으면 백그라운드 작업이 멈추고 진행 표시가 결과로 바뀌지 않는다 |
| `--max-instances=1` | 생성 작업 상태(`_generation_jobs`)를 프로세스 메모리에 둔다. 인스턴스가 둘 이상이면 진행 폴링이 다른 인스턴스로 가서 작업을 못 찾고 404가 난다 |
| `--memory=4Gi --cpu=2` | 임베딩 모델(KoE5)이 프로세스에 상주한다. 이보다 작으면 모델 로드 중 컨테이너가 죽는다 |
| `--add-cloudsql-instances` | Cloud SQL 유닉스 소켓을 마운트한다. 없으면 배포 환경에서 DB에 붙지 못한다 |

콘솔이나 Cloud Build 트리거로 배포를 관리하더라도 위 네 가지는 동일하게 적용돼 있어야 한다.

### 1.2 리버스 프록시 뒤 스킴 인식

Cloud Run은 TLS를 종료한 뒤 컨테이너에는 평문 HTTP로 요청을 넘긴다. `url_for()`가 절대 URL을 만들기 때문에, 앱이 스킴을 그대로 믿으면 HTTPS 페이지에 `http://` 자산 링크가 박히고 브라우저가 혼합 콘텐츠로 차단한다. Dockerfile 실행 명령의 `--proxy-headers --forwarded-allow-ips '*'`가 `X-Forwarded-Proto`를 신뢰해 원래 스킴을 복원한다.

### 1.3 콜드스타트

`--min-instances`는 기본값 0이다. 유휴 상태에서 첫 요청은 컨테이너 기동과 임베딩 모델 로드를 기다려야 해 눈에 띄게 느리다. 이미지 빌드 시 KoE5 모델을 미리 받아 캐시하며, 런타임에는 `HF_HUB_OFFLINE=1`을 기본 설정해 이 캐시 없이는 첫 요청이 실패하게 한다. `--min-instances=1`로 상시 기동할 수 있으나 인스턴스가 상시 과금되므로, 시연 시점에만 올리고 끝나면 되돌린다.

### 1.4 배포 환경의 DB 접속

DB 접속 방식은 코드가 `K_SERVICE` 환경변수 유무로 자동 분기한다(`app/lib/db.py`). Cloud Run에는 이 변수가 항상 있으므로 유닉스 소켓 경로로 붙고, 로컬에는 없으므로 `DB_HOST`/`DB_PORT`(Cloud SQL Proxy)로 붙는다. 따라서 배포 환경에는 `DB_HOST`/`DB_PORT` 대신 `INSTANCE_CONNECTION_NAME`을 넘겨야 하며, 로컬 `.env`를 그대로 올리면 안 된다.

## 2. 공통 유틸리티 (INFRA-002)

여러 에이전트가 공유하는 DB 연결, LLM 호출, 타입 계약, 인증을 제공한다.

| 파일 | 역할 | 사용처 |
| --- | --- | --- |
| `app/lib/db.py` | Cloud SQL 연결 헬퍼. `K_SERVICE` 유무로 접속 방식 자동 분기 | DB가 필요한 모든 에이전트 |
| `app/lib/gemini.py` | Gemini API 호출 공통 함수. API 레벨 실패(타임아웃·429·5xx)만 재시도 | LLM 호출이 필요한 모든 에이전트 |
| `app/lib/types.py` | 전역 공통 타입 정의(Pydantic v2). 팀 데이터 계약의 정본 | 전체 에이전트. 변경 시 전원 합의 필요 |
| `app/lib/auth.py` | 세션 인증, 관리자 권한 판정, 생성 횟수 제한 | `app/main.py`의 라우트 전반 |

**DB 스키마의 정본은 이 문서가 아니다.** 실제 운영 DB의 테이블·확장·인덱스는 [`REQ006-DB스키마.md`](REQ006-DB스키마.md)를 따른다. 코드에 DDL을 포함하지 않는 것이 팀 규약이며, `app_user`에는 `SELECT`/`INSERT`/`UPDATE`/`DELETE`만 부여되고 DDL 권한은 애초에 부여하지 않는다. 로컬에서 이 DB에 붙는 절차는 [`REQ006-DB접속안내.md`](REQ006-DB접속안내.md)를 따른다.

### 2.1 시각 처리 규약 (저장 UTC / 표시 KST)

| 구분 | 규약 | 근거 |
| --- | --- | --- |
| 저장 | 시각 컬럼은 `timestamptz`, 기본값 `now()` — 항상 **UTC**로 들어간다 | 지역이 늘거나 서머타임을 쓰는 지역이 끼어도 과거 기록의 의미가 흔들리지 않는다 |
| 조회 | DB 세션 타임존을 지정하지 않는다. psycopg가 UTC aware `datetime`을 돌려준다 | 지역 시간 변환을 DB 설정에 의존하면 접속 경로마다 값이 달라진다 |
| 비교·판정 | 세션 만료, 레이트리밋 윈도우는 **UTC 그대로** 비교한다 | 변환 없이 비교해야 정확하다. 레이트리밋은 SQL 안(`created_at > now() - interval`)에서 끝난다 |
| 표시 | 화면에 찍기 직전에만 **KST(Asia/Seoul)**로 변환한다. Jinja 필터 `kst`(`app/main.py`의 `to_kst`) 한 곳만 쓴다 | 변환 지점이 하나여야 누락·중복 변환이 안 생긴다 |

주의:

- 템플릿에서 `created_at.strftime(...)`을 직접 호출하지 않는다. `{{ item.created_at | kst }}`를 쓴다. 직접 호출하면 UTC가 그대로 찍혀 KST 기준 9시간 뒤처진 시각이 나온다.
- 서버에서 "지금"이 필요할 때 naive `datetime.now()`를 쓰지 않는다. Cloud Run 컨테이너의 로컬 시간은 UTC다. 표시용이면 `datetime.now(KST)`, 저장·비교용이면 `datetime.now(timezone.utc)`.
- `to_kst`는 tz 정보가 없는 값을 UTC로 간주한다. `app/lib/auth.py`의 `_is_expired`와 같은 규약이다.

## 3. 계정·이력·사용량 관리 (INFRA-003)

| 항목 | 내용 |
| --- | --- |
| 인증 방식 | 세션 기반(JWT 아님). 서명된 세션 쿠키를 발급하고 세션 데이터는 `sessions` 테이블에 저장 |
| 권한 | `users.role`로 `user`/`admin` 구분. 관리자 경로는 role 검사를 통과하지 못하면 접근 차단 |
| 사용량 제한 | 일반 계정 일 5회 / 주 15회 롤링 윈도우. 관리자는 제한 없음. 캘린더 자정 리셋은 경계 우회가 가능해 사용하지 않는다 |
| 생성 이력 | 실행마다 입력값·매핑 결과·생성물·종료 상태를 `lesson_requests`에 저장 |
| 마이페이지 | 이력 목록 조회·과목 필터·상세 열람·재출력·삭제(soft-delete), 담당 학년 기본값 설정 |
| 재출력 | 저장된 생성물로 DOCX만 다시 만든다. 파이프라인을 재실행하지 않으므로 언어모델 호출이 없고 사용량에도 포함되지 않는다 |
| 관리자 화면 | 성취기준 청크 검색·조회·수정. 데이터 조작은 관리자 화면 라우트가 직접 담당하며 별도 API 계층을 두지 않는다 |

수정 대상에서 제외하는 필드(청크 식별자, 과목, 학년군, 성취기준 코드)와 그 이유는 PRD 4.6을 따른다.

## 4. 웹 인터페이스 (SITE-001)

사용자가 AI 개념과 학년을 입력하고 결과를 확인하는 화면을 제공한다.

| 항목 | 내용 | 핵심 포인트 |
| --- | --- | --- |
| 입력 | 사용자 폼 입력(AI 개념, 대상 학년). 과목은 입력받지 않는다 | Jinja2 서버사이드 렌더링 + htmx |
| 처리 | 폼 제출 시 작업을 등록하고 진행 패널을 즉시 반환, D의 `run_pipeline()`을 백그라운드로 실행 | 브라우저는 진행 패널을 폴링해 단계 전환을 표시 |
| 출력 | 교안·활동지 결과 화면. 매핑 근거("이 성취기준을 고른 이유")를 함께 표시 | 세부 렌더링은 C가 소유, 화면 골격은 E가 제공 |
| 예외 처리 | 파이프라인 실패 시 사용자 친화적 에러 메시지 표시 | 스택트레이스 노출 금지 |

라우트 전체 목록은 저장소 README를 정본으로 삼는다.

## 5. 성능 요구사항 (NFR 연계)

| NFR ID | 항목 | 기준 | 비고 |
| --- | --- | --- | --- |
| NFR-006-1 | 배포 가용성 | 배포 실패 시 이전 리비전으로 자동 유지 | Cloud Run 기본 롤백 |
| NFR-006-2 | 요청 타임아웃 | 파이프라인 응답(재시도 포함 최대 60초)을 넉넉히 수용 | Cloud Run 서비스 타임아웃 설정 필요 |
